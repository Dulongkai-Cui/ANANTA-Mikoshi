版本：1.0｜2026-10-18｜产品负责人：Codex｜实现：Claude。
状态：执行包编制完成，准入结论见[准备度审查](../../../SBS/evidence/SBS-0007/readiness.md)；实施状态以[SBS-0007](../../../SBS/SBS-0007-login-saas-shell.md)为准。

## 1. 一句话设计指令

**构建具有 Apple 生产力软件质感的 Mikoshi 工作台。以 macOS 系统设置式的清晰结构、精细控件和稳定空间关系为参考：银白与浅灰中性色、清晰实色内容面、少量蓝色交互强调、准确的中文字重和间距。让用户第一眼知道所在位置、当前内容和下一步动作。通过一致的排版、对齐、边界、焦点、按压反馈与短促连续的过渡体现品质。所有判断服从易读、效率与可操作性。**

这是用户已经选定的一套方向，直接打磨一版。无需重新要求用户挑风格，也不强制同时制作多个方案。品牌使用 `Mikoshi`，辅助名 `ANANTA`；产品语言默认简体中文。Apple 是设计参考，应用不使用 Apple 标志、系统窗口红黄绿装饰按钮或未经许可的专有资源。

## 4. 视觉与组件细则

遵守 FE-01～52 的适用项。本文指定方向，沿用规范v0.1的颜色/字号/间距基线；本步不另造第二套色板。默认跟随系统主题，提供浅色/深色选择。主要视觉评审采用浅色，同时验证深色。

| 区域 | 具体设计要求 |
|---|---|
| 登录 | 单列表单约360–400px宽、最大宽度随视口收缩，整体垂直从容；窄屏/软键盘出现时可滚动。清晰的Mikoshi字标、标题与一行说明；没有营销Hero、背景视频或宣传数字 |
| 外壳 | 桌面侧栏232px、可折叠为64px；顶部56px。侧栏浅灰、内容实色白/深色surface，边界细而清楚。主内容padding24px，窄屏16px |
| 导航 | 首页在最上，六业务板块紧随；个人设置和用户菜单放底部/固定通用位置。选中态同时用形状/底色和文字强调；折叠后有可读提示与accessible name |
| 内容 | 标题24/32、区块18/26、正文14/22、较长说明16/26、辅助12/18；中文不负字距、不极细淡灰。主内容铺开利用空间，阅读说明限制行长 |
| 控件 | 统一系统字体与中文回退、图标族、圆角、边框和焦点。普通控件圆角6px、卡片10px、浮层12px；32–40px桌面控件，触摸关键目标44px |
| 层级 | 通过间距、实色层和分隔组织；少量轻阴影只服务浮层/层级。避免卡片套卡片。透明/模糊最多用于小范围浮层，实色回退仍清晰 |

字体使用系统回退，不下载SF字体；图标可用统一的Lucide组件。品牌点缀服务操作和导航，不能把所有文字/卡片染蓝。优先做好的“苹果感”是比例、对齐、材质克制、反馈连续，而非堆砌磨砂玻璃。

## 5. 登录、会话与通用交互

### 5.1 明确的演示登录闭环

提供两个完全虚构的演示身份（例如林序、许澄），固定ID；邮箱使用`.invalid`域。提供“填入演示账号”或账号选择控件，公开演示密码；提示“本地演示，请使用演示账号”。邮箱/密码仍为完整可用表单，支持粘贴、密码管理器、密码显示切换、Enter提交和字段标签。

提交状态：未输入/格式错误 → 字段内错误；错误凭据 → 表单级错误；正确凭据 → pending → 成功进入目标页。pending禁止重复提交但不让焦点丢失；失败保留输入。正常演示无需人为延迟；测试通过可控制的adapter延迟验证pending，不把故意等待用于展示动画。

`AuthGateway`定义`getSession/signIn/signOut`及可辨识错误；demo实现独立。会话只在sessionStorage保存版本、虚构用户ID及必要的非敏感演示信息，不保存密码、访问令牌或真实凭据。它只是模拟路由状态，不能宣称实现安全认证。

sessionStorage不可用或写入失败时，signIn返回“本地会话无法建立”，保留输入并停留登录页；不静默切换为内存会话、不显示登录成功。读取不可用/损坏时回到登录并解释本地会话问题。

显式配置`demo`模式，登录页与工作台持续但克制地显示“演示环境”。正式模式adapter未接入时明确返回未配置，不能自动回落到假登录。README说明如何切换/验证该失败状态；本步不需要部署生产模式。

未登录深链接先到登录，成功后回到允许的内部目标；默认首页。`returnTo`以本规格路由白名单校验，拒绝外域、协议相对路径、编码绕过和不支持的路径。无效/损坏会话回到登录；检查会话期间显示中性加载壳，不闪现已登录内容。登录状态访问`/login`回到首页。

退出清会话、身份相关内存状态和搜索内容，回登录；后退不能恢复已登录界面。个人布局可保留在以演示用户ID隔离的本地键中，下一次用同身份登录可恢复；两身份之间不可串布局。跨浏览器真实多人安全隔离不在本步验收范围。

### 5.2 搜索、主题、设置、未保存草稿

- 全局搜索按钮与Ctrl/Cmd+K打开导航搜索。标签写“搜索页面”；只搜索上表真实页面名/别名，不冒充业务全文检索。中文输入法组合期间不抢Enter；方向键、Enter、Esc可操作，关闭后归还焦点。空结果有明确文案。
- 主题选择：跟随系统/浅色/深色。减少动效默认跟随系统，用户可进一步减少，不能通过产品设置强制覆盖系统reduce。偏好有版本化本地存储，刷新有效；不可存储时提示本次会话生效。
- 所有本地存储访问捕获不可用/损坏/超额错误。设置失败不报告持久保存成功。主题初始化避免明显错误主题闪烁与hydration异常。
- 首页存在未保存布局时，站内导航、退出或切换演示身份给出“继续编辑/放弃更改”；放弃只丢草稿。外部刷新/关闭按浏览器支持使用原生离开提示，不能承诺自定义文本；保存过的布局始终保留。
- 浏览器前进/后退同样不能静默丢草稿；允许保留草稿并在返回首页时恢复，显示“还有未保存的布局”，无需篡改浏览器历史。程序内导航仍使用上述继续/放弃选择。
- 小屏侧栏变抽屉，打开/关闭与路由跳转焦点合理；选择目的页后关闭。对话框/搜索有焦点管理、Esc与返回焦点，无遗留遮罩。

## 6. 可定制首页：本轮必须做完整的最小闭环

默认四张登记卡片，不做任意HTML/脚本/插件编辑器：

| 类型 | 默认展示 | 可用操作 |
|---|---|---|
| 业务概览 | 六板块接入状态，明确“未接入”；未知数据用“—”并解释，不填0 | 跳转对应业务入口 |
| 我的待办 | 空态“尚未接入任务数据” | 查看整体业务中台入口 |
| 近期工作 | 空态“尚未接入业务动态” | 查看联动管理入口 |
| Agent动态 | 极少量固定合成状态例子，持续标“状态示例”，含等待/运行中/失败等文本；时间用固定样例时间且标示例 | 展开只读示例说明，不能启停真实Agent |

页面上方是标题、简短说明、日期/身份必要信息与“编辑首页”。不要为了填满版面编造KPI或播放随机跳动的曲线。Agent示例只解释状态显示方式，不表示系统已有常驻AI运行；工作Agent与VPC虚拟角色分开解释。

编辑模式：卡片添加面板、移除、向前/向后移动、宽度预设（标准/宽）、保存、取消、恢复默认。每类卡片最多一个实例；重复添加项明确不可再添加；允许移除全部并给出添加入口。无需拖拽即可验收；如果主动加入拖拽，必须保留点击与键盘替代。

桌面按有序网格排列，宽卡占满可用行；窄屏统一单列，只改变渲染，不覆写桌面宽度偏好。DOM阅读顺序与配置顺序相同，不能视觉排序与键盘顺序不一致。

进入编辑复制已保存布局为草稿。取消恢复；恢复默认只改草稿，点击保存才持久化；保存成功退出编辑，失败保留草稿/可重试且不显示成功。排序边界按钮正确禁用；修改状态通过可访问反馈表达。

`DashboardRepository`暴露load/save，布局具备schemaVersion、userId、revision、实例ID、type及size/order。demo按用户独立键存储，仅保存配置；保存检查当前revision，冲突保留草稿并支持重新载入。未知类型/重复ID/损坏schema不致页面崩溃，提示后用可恢复默认，不静默覆盖原数据；迁移或覆盖须在用户保存时发生。读取失败和写入失败均有测试。

重新载入如果会丢当前草稿，必须明确确认放弃。revision只承诺演示级陈旧版本检测：同身份两个实例读取相同revision，A先保存，B随后保存应报冲突。localStorage读/比较/写并非原子操作，本步不承诺跨标签同时写入或真实多人并发安全。

卡片登记表持有支持尺寸、标题/语义、来源、数据性质、更新时间/未接入、状态与合法下钻。没有真实指标就不虚构metricId；用明确的空值/不适用和接入状态表达。后端query/权限/指标口径在未来adapter实现，UI不得因此出现“已连接”或“权限校验成功”。

## 7. 代码结构与后续接入边界

建议结构如下，允许同职责的合理命名差异；路由文件保持薄层。

```text
frontend/mikoshi-web/
  src/app/                  # login、受保护路由组、错误/404/loading
  src/components/ui/        # 选定的shadcn原语与项目基础控件
  src/components/shell/     # 侧栏、顶栏、搜索、用户菜单
  src/features/auth/        # 表单与会话状态
  src/features/dashboard/   # 卡片登记、编辑状态、布局校验
  src/features/business/    # 六板块描述配置及共用入口结构
  src/features/settings/
  src/contracts/            # AuthGateway、DashboardRepository等
  src/adapters/demo/        # 演示会话、配置存储、合成示例
  src/styles/               # 唯一semantic tokens及全局样式
  tests/                    # 关键逻辑测试与浏览器流程
  README.md
  THIRD_PARTY_NOTICES.md
  package.json
  package-lock.json
```

组件通过合同调用adapter，不直接到处读写localStorage。采用需要的最小状态管理方式，不为骨架引入微服务、通用插件运行时或庞大状态库。导航与业务元数据只维护一处；token集中映射，组件不得散写另一套颜色/字号/动效。错误边界覆盖关键区域；只因一个卡片异常不得使整个Shell不可导航。

未来真正的服务端认证、HttpOnly会话、授权、多人并发、数据库、持久Agent、可观测性和部署是独立集成工作。本步只留下清楚接口和状态，不假设后端权限可由前端按钮决定。后续替换adapter不应要求重写布局/表单/卡片外壳。
