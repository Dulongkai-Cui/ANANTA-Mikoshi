# KOL 本机管理

本模块按根 SBS-0015 实现。达人档案、合作和具体发布计划独立建模，同一达人可以拥有多项合作；零数据分析页在 legacy 展示层，不把管理记录算作平台效果。

| 文件 | 职责 |
|---|---|
| model.ts | 达人/合作/排期唯一合同，身份、链接、日期、引用与时间冲突校验 |
| repository.ts | schema/revision、身份隔离、本机错误、锁与读回确认 |
| kol-provider.tsx | 身份共享状态、存储事件、冻结编辑版本、保存及草稿守卫 |
| editors.tsx | 三类表单，字段分组、可见错误、焦点与保存反馈 |
| shared-ui.tsx | KOL 公共展示、指标/表格/分页及排期状态确认 |
| accounts-page.tsx | 入库、搜索、分类和状态筛选，编辑与创建合作 |
| progress-page.tsx | 九阶段看板/表格、负责人/档期/下一步与阻碍 |
| plans-page.tsx / calendar-page.tsx | 同源列表与42格月历，日期键盘、右侧详情、改期/取消/撤下/恢复 |

路由为 `/kol/accounts`、`/kol/progress`、`/kol/plans`、`/kol/calendar`，复用既有界面原语和 `lib/calendar-dates.ts`，不读取三方私有仓储。四页挂同一 `KolEditors`，草稿保存在外层身份 Provider；跨路由/Back 后可返回原页继续编辑。

仓储 key 为 `mikoshi:kol:initial-20261019:<encodedUserId>`，schema=1。首次读取无值返回空集合，不自动写入或种子化，也不改旧 KOL 快照配置或三方存储。修改需 expectedRevision；成功写入且读回一致才更新已保存资料。损坏、配额和冲突保持原串和草稿，不自动修复覆盖。Web Locks 可用时串行化；缺少时仅写前版本检查，不是服务器并发保证。

平台+账号标识入库后不可换，B站数字去前导零，其他平台只去首尾空格、保留大小写，不按昵称合并。主页仅允许无凭据 http(s) 链接。联系人选填，不预置任何真实人员；粉丝/参考价/合作报价未知为 null，实际0与未知区分。参考价和本次报价独立，不生成预算、消耗或结算。

初筛通过不等于签约；阶段与档期状态独立，人工“待复盘/已完成”不生成发布成功。制作周期和最迟下单日仅管理字段，不执行采购。新合作禁止选择已停用达人；排期新建/恢复禁止停用达人或已取消合作。同一达人跨合作、同一时刻的有效计划冲突；取消/撤下不占该时刻。

停用达人/取消合作不会删除已有计划，计划会提示待核对。取消保留可见记录；撤下从默认计划/月格/当天栏隐藏，筛选已撤下可查看恢复。恢复重新校验身份/关系/冲突。状态确认冻结记录 updatedAt，不以已变化记录执行确认；操作不触及外站帖子。

所有管理资料仅当前浏览器/当前演示身份，清理站点存储会丢失。没有服务器权限、多人数据库、批量导入、抓取、自动发布、消息发送或采购结算；未来接后端需新适配器与明确迁移，不静默丢弃本机资料。
