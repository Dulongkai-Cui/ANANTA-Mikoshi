## 1. 设计原则与范围

**FE-01 工作优先。** 每页说明用户要完成的事、当前状态、下一动作及结果依据。清晰的中文、稳定位置、可比较的数据和及时反馈优先于装饰。信息密度由任务决定；指标总览可以留白，业务列表允许紧凑。

**FE-02 可信状态。** 页面区分事实、计划、草稿、推断、模拟和未知。加载不显示假零，提交不显示假成功，Agent 生成不自动变成正式业务状态。不能靠隐藏入口代替权限控制。

**FE-03 统一且可调整。** 同一含义使用同一组件、词汇和语义 token；板块差异通过内容和流程体现。项目定义自己的设计规范，第三方技能的个人偏好不能自行改写它。

**FE-04 即时、连续、可恢复。** 输入立即获得视觉反馈，真正提交按明确动作发生。动画不锁住操作；关闭重开、返回列表、网络重连后保持可理解的上下文。请求已发出但结果未知时，先核实。

**FE-05 当前视觉方向。** 用户最新选择无限大B站数据系统的深蓝侧栏、浅灰蓝工作区、白色数据卡片、蓝色选中态，品牌为巫女小狐狸与MIKOSHI（DEC-018）。这替代SBS-0007的全中性苹果外观；苹果生产力软件所强调的清晰层级、稳定空间、响应和克制动效继续作为质量要求。统一外壳不改历史数据含义；两个历史工作台的内嵌复用边界和离线口径见[SBS-0008规格](../../Product/handoffs/SBS-0008/SPEC.md)。

## 2. 信息架构与页面骨架

**FE-06 一级入口。** 当前顶部顺序为MIKO、我的工作台、三方号、KOL、联动管理、创意管理。入口采用图标、持续可见底色/边框的小按钮外观，选中项实心主色；仍使用真实导航链接。侧栏只显示当前业务的真实子页。VPC虚拟社区归属创意管理，规范路径/creative/vpc，旧/vpc只做兼容跳转；VPC页面顶栏选中创意管理，点击该顶栏按钮可回创意总览。整体业务中台当前撤下，/business为404。MIKO仅静态AI入口预览，不伪造会话、回复或任务；输入/发送禁用且说明未接入。我的工作台恢复营销项目总览，下设任务看板、项目时间轴、人员进度和KOL协作概览；默认登录进入/dashboard。使用独立版本化的本机工作区，既有个人布局不读写或删除。KOL/三方号保留全部已存在子页。搜索同时包含子页及归属提示；采集器、模型、向量库等技术名词不成为普通人员的一级业务导航。

**FE-07 桌面骨架（v0.5.1）。** 左侧导航宽13.5rem（默认216px），随文字缩放；收起64px，二级页面仍有图标、可访问名与提示。顶栏最小高56px，桌面细指针业务按钮与搜索高36px，手机/粗指针保留至少44px触达；上下留白4px，顶部业务入口与搜索/环境标识同层；窄屏将业务导航放到第二行，并可在独立区域横向滚动，保留可见滚动提示与键盘焦点入视。手机抽屉只展示当前业务子页和个人入口。页面内边距桌面32px，紧凑16px；内容间隔优先16/24px。表格占可用宽度，阅读/表单内容建议约720–960px；详细数据视图不强制同一最大宽度。中文长标签和缩放可触发布局调整，不以裁字维持固定尺寸。

**FE-08 页面层级。** 页面标题与主要状态 → 常用动作 → 筛选/视图 → 主内容 → 相关证据。常规页面一个明确主动作，其余动作降级为次按钮或有文字的菜单。列表返回必须恢复筛选、排序、分页/游标和适当滚动位置；可分享的对象/查询有稳定 URL，权限仍在打开时验证。URL 不放凭据、私密正文或无权元数据。

**FE-09 详情形态。** 快速查看可用右侧非模态面板；复杂编辑、长文审批、可分享详情用独立页面。对话框用于有明确开始结束的短任务。模态与非模态的焦点、背景可操作性必须一致，不做看似抽屉却无法解释为何锁住全页的混合形态。最多一层主模态；必要子选择器返回父任务，不叠三四层遮罩。

**FE-10 全局定位。** 顶部主导航切业务，侧栏切当前业务子页；页面标题及选中态表达当前位置。对象内标签页与业务导航语义分开，不为普通站内链接伪造Tabs键盘合同。跨板块沿用未保存守卫，保留真实href与新标签行为；历史工作台再次进入恢复记忆子页及筛选，不强制回首页。返回后不丢工作。全局搜索结果按当前权限过滤，展示类型、所属项目和更新时间。

## 3. 视觉语言与 tokens

**FE-11 token 唯一来源。** 后续实现集中维护 semantic tokens；业务组件引用 `text.primary`、`surface.default`、`action.primary` 等角色，不散写色值/阴影/时长。框架对应的 CSS 变量映射只维护一处。颜色、字号、间距、圆角、层级与动效都版本化。下面为v0.3执行基线；运行时唯一来源为[应用tokens](../../frontend/mikoshi-web/src/styles/tokens.css)。实际验收必须绑定源码与截图。

**FE-12 色彩约束。** 状态同时有文字/图标，不能只靠红绿。主色不等于成功色；模拟标签不借用成功绿表达“真实已验证”。大表面不用高饱和色，图表系列与状态色分开。disabled 仍可读，且与 loading、只读、无权限不同。浅/深色要各自设计和检查，不能简单反色。

数值仅在表中指定的实色搭配下可检验；透明度、hover、选中底、图表填色改变后必须重新测量。文本默认要求 4.5:1，重要控件边界/状态视觉依据要求 3:1；装饰分隔不承担这一职责。具体标准见 FE-44 与官方来源研究。

### 3.2 字体、排版、数字

**FE-13 字体（v0.3）。** 使用系统 sans-serif 与完整中文回退，例如 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。不下载/打包 Apple 专有字体模拟 macOS；选择外部品牌字体须核对许可、中文覆盖、加载和离线回退。

| 角色 | 默认字号 / 行高 | 字重 |
|---|---|---|
| 页标题 | 27px / 38px | 600 |
| 区块标题 | 16px / 24px | 600 |
| 正文、表单、表格 | 14px / 22px | 400，强调 500/600 |
| 长文阅读 | 16px / 26px | 400 |
| 辅助标签 | 12px / 18px | 400/500；不得承载唯一关键结果 |
| 首页指标 | 28–32px / 36–40px | 600 |

数字使用本地Bahnschrift/DIN Alternate/Aptos/Segoe UI回退，不下载字体。英文眉题只作次级定位，不承载唯一业务含义。

实现字号使用 rem/em 等可缩放方式（表中 px 是默认 16px 根字号下参考）。中文正文不使用负字距；长标题换行，禁止默认全大写、整段居中、极细灰字。正文与密集表格的可读性优先于“更像苹果”。

**FE-14 数字与时间。** 可比较数值右对齐并使用 tabular numerals，编号/代码可用等宽字体。金额有币种、单位、口径与精度；使用确定的格式/金额类型，不靠前端浮点运算改财务事实。`0`、`—（无数据）`、`加载中`、`读取失败`分别显示。短格式“1.2 万”应能查看准确值，导出保留实际口径。用户界面以项目约定时区显示，默认 Asia/Shanghai；相对时间可查看完整日期时间及时区。

### 3.3 间距、圆角、图标与层级

**FE-15 尺度（v0.3）。** 间距使用 4/8/12/16/24/32/48px；2px仅用于图标等光学校正。控件圆角7px，普通卡片14px，浮层14px，pill 仅用于标签。图标 16/20px 为主，采用一套风格；纯图标按钮必须有可访问名称。不要将所有正文包成卡片或给每块信息加投影。

**FE-16 层级。** 静态区域通过间距、实色底和细分隔区分；轻阴影用于浮起的交互层，避免浓重外发光。默认层级顺序为内容 < sticky < popover < modal/scrim < toast，实际数值集中在 overlay 管理处。嵌在模态内的选择器挂到正确层与焦点范围；不能靠无限增大 z-index 补布局问题。toast 不盖住确认按钮或键盘焦点。

**FE-17 主题与品牌。** 默认跟随系统，并允许个人选浅色/深色；登录后的个人偏好持久化由后端合同实现，初次页面不闪错主题。颜色方案属于个人偏好，团队布局不覆盖个人主题。减少动效/降低透明度可独立设置，不能与主题绑在一起。科幻元素可用于品牌标识、细节强调和可关闭的 Agent 概览，不替代业务状态文字。

## 4. 组件与状态合同

**FE-18 组件层次。** 基础控件 → 有语义的共用模式 → 业务组件 → 页面。设计系统不调用业务 API、不决定权限或 KPI；业务组件通过明确 props/合同消费数据与 allowed actions。允许使用选中的 shadcn/ui 部件作为实现基础，但未来只引入需要的组件与依赖，保留来源/许可证，不把整个上游仓当应用目录。原生语义优先于自造 div 控件。

| 组件/模式 | 必须规定的行为 |
|---|---|
| Button / IconButton | 默认、hover、pressed、focus、disabled、pending；pending 保留宽度及动作名称，阻止同一动作重复提交 |
| Input / Select / Combobox | 持久 label、说明、必填/可选、错误关联、清除方式；中文 IME 输入期间不触发搜索/提交，Enter 语义明确 |
| Dialog / Sheet / Popover | 模态语义、初始焦点、Esc/关闭、焦点归还；未保存内容不得静默丢失；Popover 定位随触发器和视口调整 |
| Table / List | 筛选、排序、密度、分页、选择范围、空/错/加载、操作权限；尽量保持稳定行高与列宽 |
| Tabs / Segmented control | 明确导航或就地切换，焦点与选中不同；按采用的键盘模式实现，不仅颜色变化 |
| Toast / Inline notice | toast 报短期回执，持久错误/审批待办在页面可回看；关键状态不只出现在消失的 toast 中 |
| File / Asset preview | 文件名、类型、版本、权限、处理进度/失败；上传/预览失败不假装已形成正式资料 |
| Status / Avatar | 有文字身份与状态；人与工作 Agent、VPC 角色、外部服务可辨识，头像不承担唯一信息 |

**FE-19 状态矩阵。** 页面先列适用状态再实现，不仅提供成功样张：

| 状态 | 显示与操作 |
|---|---|
| 首次加载 | 稳定占位与可理解提示，不显示虚构业务数值 |
| 后台刷新 | 保持已知且仍有权的数据，标记刷新；不闪成全页骨架 |
| 真空数据 | 说明没有记录，有权限时提供创建/导入入口 |
| 筛选无结果 | 显示当前条件并能清除条件，不误导为系统没数据 |
| 未接入 | 说明此数据源尚未接入；与空记录不同 |
| 部分/过期数据 | 标明覆盖范围、最后成功更新时间和失败来源；汇总注明缺项 |
| 读取失败/离线 | 保留允许保留的上下文，明确重试影响；不能声称写入成功 |
| 无权限/权限撤销 | 不显示原敏感内容与缓存；给适当申请/返回入口，不能泄漏无权对象标题 |
| 保存冲突 | 保留本人草稿，显示版本冲突，提供核对/重新加载/另存的合适选择 |
| 结果未知 | 显示动作标识与核查入口，不直接给“重新执行”按钮 |

**FE-20 表单。** 有明确保存/取消和脏状态；校验兼顾输入与提交，不在每次键入时打断。服务端错误映射到字段和摘要，保留合法输入。自动保存仅在合同允许的草稿/偏好上采用，需有保存中、已保存、失败、冲突反馈；审批、发布、付款等正式动作使用明确提交。

登录和重新认证允许适当的密码管理器、粘贴和自动填充，不要求用户无辅助记住/抄写验证码或完成认知谜题；具体认证方式遵守已选身份服务合同。表单标签不只用placeholder，必填/出错不能只用颜色。上传预览和业务图片提供适当替代文字；装饰图标不重复播报。

**FE-21 表格与批量操作。** 列头说明单位/可排序性，长文本可展开或进入详情；不强迫所有列同时挤进屏幕。默认行高舒适 44px、紧凑 36px；多行内容自适应，密度设置不等于缩小字号。选择范围明确为当前页/明确记录/全部筛选结果；切换条件后不得暗中扩大选择。执行前显示数量、对象范围和动作，混合权限/部分失败逐项回执。实时更新不在用户选择、阅读或编辑时突然重排行；提示有新数据，由用户刷新或安全合并。

**FE-22 图表。** 图表服务一个问题，必须有标题、单位、时间窗、数据来源、更新时间及无数据状态。类别与时间轴可读，颜色有图例与其他区分方式；重要数据提供表格/文本等效读取，hover tooltip 不是唯一出口。柱图默认从零起，截断轴明确说明；折线不跨缺失区间伪连线。多项目汇总不因缺源显出虚假完整率；模拟与真实不放在未标记的同一系列。

## 5. 可定制首页

**SBS-0016当前实施（DEC-025）：** 用户指定marketing_project_manager_v2.html作为核心框架，取代SBS-0010工作台暂空例外。首页固定六项项目指标，其余四区块可在项目设置中显隐/排序，保存与取消明确；任务、事件线和人员视图共用新工作区合同。KOL概览只消费现有KOL数据，不另建名册。默认零态保留完整图表；示例仅显式只读且不落盘。原型在线API不接入。旧DashboardPage仍不挂载，旧布局原串不读写/迁移/清除。实施与验收范围以SBS-0016为准，不宣称多人云端共享。

**FE-23 首屏职责。** 首页回答“我关心什么、发生了什么、下一步去哪里”。它显示和引导业务，不另建事实副本。编辑首页改变布局/卡片配置，改变账号、费用、审核结果必须进入对应业务动作。

**FE-24 编辑流程（默认 v0.1）。** 浏览 → 点击编辑 → 形成布局草稿 → 添加/移除/排序/调整尺寸及筛选 → 预览 → 保存或取消。保存个人布局只影响本人；团队模板发布单独表达影响范围与编辑资格。普通布局保存不增加无意义确认弹窗。清空布局或丢弃大量未保存修改提供撤销/明确确认。

**FE-25 卡片合同。** 每张卡片声明：稳定实例 ID、组件类型/版本、布局约束、登记指标 ID/口径版本、查询参数白名单、局部筛选、数据标签（真实/计划/模拟）、来源、时间、状态、可用下钻和权限。实例名与布局不存敏感数据副本，不开放任意 HTML/脚本/SQL。全局筛选影响哪些卡要可见，局部覆盖必须有标记。

**FE-26 交互可达性。** 拖拽只在编辑态且有独立手柄；抓取点连续，支持取消、边界和自动滚动。始终提供“向前/向后移动”“尺寸选择”等按钮或菜单替代；键盘操作能移动并播报新位置，不要求用户必须会拖动。缩放保持卡片可读，过小尺寸拒绝并解释。窄屏采用线性顺序，不能保存窄屏配置时破坏桌面布局；不同布局之间的映射/断点策略由执行包给定。

**FE-27 持久化与协作。** 配置区分个人、团队模板、共享视图和默认首页；复制布局不会复制作者权限。保存携带期望版本，冲突保留本地草稿并要求核对，不静默最后写入覆盖。先以乐观版本控制支持多人；不因40人规模默认引入协同编辑 CRDT。若团队编辑锁、实时协作或模板升级需要更复杂行为，另写具体合同。

**FE-28 数据读取边界。** 刷新首页读取已有结果，不自动新建采集/模型任务。共享、导出、缓存命中、实时订阅均按当前查看者权限处理。撤权清除已不可见缓存，受限卡片用安全占位而非透露标题/数量；缺数据不把其他来源代填为零。失败卡片只影响自身，其他卡仍可用。保存失败、重新登录、跨设备、模板版本变化都要验收。

## 6. 业务页面的共同语言

下面约束所选页面的呈现方式，不承诺全部业务会在第一版上线，不批准总体提案中尚未确定的具体业务规则。

| 板块 | 设计要突出 | 不可混淆 |
|---|---|---|
| 三方号 | 账号/供应商归属、运营周期、内容版本、审核、发布回执、效果来源 | 草稿/已审/已提交/平台确认发布；目标 KPI 与真实结果 |
| KOL | 达人资料、合作单、报价口径、档期、交付物、确认与复盘 | 意向与签约、报价与结算；不能仅凭颜色看出是否已锁档 |
| 联动管理 | 权益/使用限制/期限、素材版本、监修轮次、交付与履约 | 可参考与可商用、已送审与已批准；授权到期要可见 |
| 创意管理 | Brief、提案版本、反馈、评审结论、制作交接与案例 | AI 点子、人工选择与正式业务事实；采用版本不能随编辑漂移 |
| VPC 虚拟社区（创意管理下） | 角色/圈层、实验条件、样本、模拟运行、报告与限制 | 模拟玩家与真实用户、工作 Agent；模拟输出不冒充市场反馈 |
| 整体业务中台（暂停，当前无运行页面） | 留作未来研究：项目/节点、跨域依赖、负责人、资源/预算口径、风险与回执 | 总览与原始业务所有权；跨板块关联不自动获得全部权限 |

**FE-29 共用模式。** 项目/人员选择、文件版本、评论/提及、审核、交接、费用引用、活动记录和 Agent 任务使用共用模式。领域差异通过 schema/配置或专门业务组件表达，避免六份近似但行为不同的基础控件。评审与交接始终指向具体版本，不只指向可能继续变化的“最新稿”。

## 7. 多人协作、登录与前后端合同

**FE-30 身份与权限。** 登录/会话过期/重新认证/无权限都需页面状态。角色和 allowed actions 来自服务端可信合同；前端禁用/隐藏只是解释与防误触。切账号、项目或权限范围时清理对应缓存/订阅/草稿归属；不能展示上一人的结果。会话失效时保护可恢复草稿，但敏感正文不得默认写入未受控 localStorage。

**FE-31 版本与并发。** 每个可编辑对象提供标识、版本、更新时间、操作者及允许操作。提交带 expectedVersion 或等效条件；冲突响应不能伪装普通网络错误并自动覆盖。用户选择重新加载前可查看/复制自己的变更；多人正在编辑的提示若没有真实 presence 支持，不能伪造。

**FE-32 请求与反馈。** 明确哪些操作可乐观更新：个人低风险偏好可在可回滚时即时反映；审批、外发、费用、授权变更以权威回执为准。double click、超时、重连均按同一业务意图去重。禁用按钮防误触不能替代服务端幂等。失败时区分可重试读取、校验问题、冲突、无权限、结果未知。

**FE-33 最小前后端合同。** 首条前端任务须给出以下字段的真实映射或标记待实现；下列是语义要求，不固定路由/数据库/命名风格：

| 合同 | 前端需要知道 |
|---|---|
| 业务资源 | stable ID、project/scope、version、状态、allowed actions、updatedAt |
| 列表查询 | 排序/筛选/分页合同、全量数的权限口径、选中范围及实时变化策略 |
| 指标响应 | metric/definitionVersion、value/unit、范围、来源、asOf、缺失/过期/模拟标记 |
| 命令回执 | action ID、accepted/finished/unknown、幂等语义、查询方式、字段错误/冲突细节 |
| Agent 事件 | job/run ID、稳定事件 ID/顺序、业务阶段、进度依据、权限安全的证据引用 |
| 布局存储 | owner/scope、layoutVersion、schemaVersion、widget config、期望版本与冲突合同 |

前端原型可使用显式 mock adapter，界面和环境标明“示例数据”；生产接线不能静默回退 mock。前端先行时同时维护这些最小合同，用一个真实业务闭环校验，再扩页面，避免把所有假页面固定后才发现数据不可提供。

**FE-34 实时与网络。** SSE/WebSocket/轮询具体技术由执行包定。UI 必须知道连接状态、最后事件/更新时间和断线后重新同步策略；不把连接断开显示为 Agent 死亡。乱序/重复事件由合同处理，页面不能重复增加计数。浏览器关闭后长期任务仍可运行，返回时从权威状态重建，不靠标签页定时器冒充服务器任务。

持续自动更新应有暂停显示/控制频率等适当机制，关键状态仍可明确提示；暂停页面更新不等于暂停服务器任务。搜索响应按查询序列处理，较旧响应不得覆盖新条件结果。持续移动、滚动或闪烁不能抢走阅读注意，也不能遮蔽停止/恢复入口。

## 8. 长期 Agent 与 AI 输出

**FE-35 身份分离。** 员工、工作 Agent、VPC 模拟玩家和外部执行节点使用明确类型标签。Agent 的启用/暂停/退役与一次任务的运行状态分开；“在线”或动画在动不代表正在执行、更不代表业务成功。助手可有名字和形象，任务状态文字与证据始终可读。

**FE-36 任务状态。** 具体枚举映射在执行包定义，至少能表达下列语义：

| 状态语义 | 页面应显示 | 操作边界 |
|---|---|---|
| 排队/等待资源 | 排队原因、提交时间；未知预计时间明确未知 | 可取消时解释取消对象 |
| 运行中 | 当前阶段、最后进展、输入范围与负责人 | 无可靠总量不画假百分比 |
| 等待人/外部系统 | 要谁做什么、为何等待、对应版本和期限 | 等待不伪装持续思考或持续消耗 |
| 部分完成 | 已完成/未完成/失败列表及证据 | 针对剩余可安全重试部分处理 |
| 成功/失败 | 可核查产物或原因、时间、下一动作 | 成功需达到业务验收，不只模型说完成 |
| 请求取消/已取消 | 请求已发与执行已停分别表达 | 关闭详情不等于取消任务 |
| 超时/结果未知 | 已发出的动作、核查状态及责任人 | 不重复外发，先对账/核查 |

**FE-37 Agent 任务详情。** 至少有目标、归属业务对象、执行身份、发起人/负责人、输入和版本、当前阶段、结果/证据、时间线、允许操作。费用展示区分预估、已计量、尚未结算，数字附时间/单位。人工接管与审批区域展示准确对象、动作、内容版本、影响与资源上限，不只提供一个泛泛的“同意”。

**FE-38 输出与证据。** 模型输出默认按不可信文本安全渲染，限制 HTML/脚本与链接行为；引用可定位且按权限打开。流式文本不自动滚动拉走正在阅读的人，提供回到最新、停止生成或取消任务的准确语义。展示理由摘要、工具动作和证据即可，不要求暴露模型内部推理。生成草稿要经过所属业务版本/审核流程才变成正式内容。

## 9. 动效规范

**FE-39 先问目的。** 只为反馈、空间关系、状态理解或直接操作添加动效。高频筛选、键盘定位、批量表格编辑不附带串场动画；不能用逐行动画延迟整表可用。动效禁用后功能与状态信息保持完整。

| token（默认 v0.1） | 时长/曲线 | 场景 |
|---|---|---|
| motion.none | 0ms | 高频操作、减少动效、需要即时完成 |
| motion.fast | 100ms | 轻微 hover/pressed 反馈；不延迟真实事件 |
| motion.normal | 160ms | 小型菜单/提示的透明度、局部状态变化 |
| motion.panel | 220ms | 低频抽屉/对话框入场；退出可更短 |
| ease.enter | `cubic-bezier(0.2, 0, 0, 1)` | 默认进入/快速响应 |
| ease.move | `cubic-bezier(0.4, 0, 0.2, 1)` | 非手势位置转换 |

这些值是 Mikoshi 起点，非照抄 Apple 系统参数；修改需在真实设备、正常速度与减速回放中评估。没有必须大于零的最短时长，减少动效可直接切换。

**FE-40 直接操作。** pointer-down 立即显示按压反馈，业务提交仍按 click/释放/键盘激活语义，允许取消。普通按钮可用颜色/阴影反馈；0.98 缩放仅可选，密集表格内不强制文字缩放。拖拽跟随当前位置，释放/反向可以连续中断；合适时采用选定库的弹簧，但参数单位按该库实际 API，不把 damping ratio 当物理 damping。默认无明显回弹。

**FE-41 运动边界。** 浮层方向与触发源一致；模态居中、锚定菜单以触发器为起点；快速反复开关不会残留透明遮罩或不可点击层。禁止默认 transition: all、全屏视差、背景持续漂移和状态闪烁。长按删除、滑动删除、弹性回弹不是关键动作唯一途径，必须有清晰可访问操作与真实撤销/确认合同。

hover 仅是增强，移动设备不依赖hover获得必需信息；运动性hover按支持hover/精确指针条件启用。纯淡入或无动画可以是正确方案，不为通过第三方评审而强行附加缩放。

**FE-42 性能与降级。** 优先动画 transform/opacity，避免大区域逐帧布局、重绘和模糊。CSS/WAAPI/JS/动画库均需以实测选择；不宣称“用了某 API 就一定走 GPU”。不要常驻给所有节点 will-change；blur/filter/clip-path/大阴影和 layout animation 需单独测量。动画不得影响IME、输入、数据滚动和焦点；发现掉帧先简化，不靠增加硬件假设掩盖。

**FE-43 减少运动/透明度。** 尊重 prefers-reduced-motion 并提供可理解的个人设置；移除大位移、视差、缩放/弹跳，可保留短淡入或直接状态切换。降低透明度与高对比偏好使用实色和明确边界；浏览器不支持相应媒体查询时仍有实色可用基线。不要用全局禁用 transform 把静态定位也破坏。

## 10. 可访问性、响应式与内容

**FE-44 Web 基线。** 以适用的 WCAG 2.2 AA 为验收目标：普通文字对比度至少 4.5:1；标准所定义的大字可为3:1，但本项目默认文本仍优先4.5:1。关键非文本控件/状态与相邻色至少3:1；并不要求所有装饰细线都达标。交互目标满足24×24 CSS px或标准规定的间距/例外条件；本项目常规桌面按钮默认高36–40px，紧凑32px，触摸主控件默认至少44×44px。44px是本项目设计目标，不冒称WCAG AA统一最低值。

**FE-45 键盘与辅助技术。** 逻辑顺序可完整操作；原生按钮/链接/表单有名称、角色和状态，焦点可见且不被 sticky/浮层完全遮挡。默认2px轮廓+2px偏移，根据背景验证；不得 outline:none 后无替代。键盘和鼠标具有等效结果，保持必要状态提示，不机械套用“键盘触发禁止一切动效”。模态正确管理焦点、关闭/返回，表格优先原生 table；采用 grid 语义则落实对应键盘交互。

**FE-46 状态通知。** 保存结果等适合用 polite live region；紧急错误才使用 assertive，避免每个 Agent token 都播报。错误与输入程序化关联，焦点可到错误摘要；工具提示支持键盘并可关闭，不遮挡主要内容。具有拖动的功能有无需拖动的单指针替代操作。语义/名称必须在自动检查之外做手动键盘和辅助技术抽查。

**FE-47 自适应。** 支持桌面主要工作；宽屏利用信息空间，小屏保留阅读、搜索、状态处理等核心流程。默认断点参考 <768、768–1199、≥1200 CSS px，以内容实际压缩点为准，不按设备品牌。页面在200%文本缩放和相当于320 CSS px窄视口的重排中不丢信息/操作；确需二维展示的复杂表格可在独立区域滚动，其标题、筛选与主要动作仍重排。图表需文本等效，不用“桌面工具”一概豁免。

允许用户覆盖适用文本间距后仍不丢内容/功能：行高1.5倍、段后2倍字号、字距0.12em、词距0.16em（按文字系统适用性处理）。这些是用户覆盖后的适应检查，不是默认中文排版必须同时设成这些值。保留缩放、文字选择和标准浏览器操作；全局快捷键可发现且避开输入框/IME与系统冲突。

**FE-48 中文和异常内容。** 中英混排、超长项目名、无空格URL、emoji、空值、长金额、数百条错误都必须有可用呈现。文本支持复制/选择，不用图片代替文字。按钮用“保存看板”“提交审核”等具体动词，错误说明发生什么、影响和可做动作，不输出服务器栈给普通用户。批量记录可展开查看，避免把长内容压进一个无法阅读的 toast。

## 11. 工程落实与发布门禁

**FE-49 设计到代码。** 先确定一套 token 映射和少量基础组件，按实际页面需求扩充；不要为未来“无限大”提前做通用插件框架。选中的第三方组件按需纳入产品代码、登记来源/版本/许可，包装公共行为；业务逻辑留在领域层。不要从 `frontend/fronted-skill/` 直接导入运行时代码或令部署依赖本机参考目录。

**FE-50 质量证据。** 每份任务至少绑定规范版本、来源 SHA、页面/状态矩阵、实际技术栈与目标浏览器、数据环境、验收步骤。功能/类型/构建测试按变化执行；截图用于视觉，交互录像/操作用于行为，网络/服务回执用于真实接入，三者互相不能替代。性能预算由执行包声明数据量、设备、网络和测量方法，不只喊“60fps”。

**FE-51 实施顺序。** 页面结构与最小数据合同并行 → 同内容风格原型 → 采用的 tokens/交互版本 → 基础组件与一条业务闭环 → 独立验收 → 扩展页面。前端先行允许调整原型，不允许为保住原型视觉而掩盖真实权限/状态/数据缺失。

**FE-52 例外与维护。** 每个例外写受影响规则ID、业务原因、替代行为、验证、责任人和退出条件。上游更新不自动更新 Mikoshi 规范；只有新的执行需求或缺陷触发修订。不得通过删掉失败场景、放宽标准或把未运行写成 PASS 完成验收。
