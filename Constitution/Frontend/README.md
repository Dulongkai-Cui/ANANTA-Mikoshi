## 先看这一页

Mikoshi 要成为一个可以每天工作数小时的业务中枢。当前先搭MIKO预览、工作台入口和四个主要业务区；VPC放在创意管理内，工作台以营销项目管理为核心，使用独立本机数据合同。设计目标是**信息清楚、反馈及时、状态可信、操作连贯，视觉精细而克制**。

emilkowalski-skills 确实包含 [apple-design](../../frontend/fronted-skill/emilkowalski-skills/skills/apple-design/SKILL.md)。它是作者把 Apple WWDC 设计思想转成 Web 指导的技能；整个库还包括设计工程、动效、性能、原型和异常数据检查。它不是 Apple 官方组件库或一个安装后自动得到苹果外观的主题。

我们采用其中关于即时反馈、空间关系、可中断交互和细节一致性的思路。中文密集表格、多人协作与长期 Agent 要优先照顾真实工作需求；大面积玻璃、持续弹跳和动画排队不会成为全局默认。

## 当前怎样开始

1. 读取[SBS-0016计划与规格](../../SBS/SBS-0016-marketing-workbench.md)和[当前交接](../../Product/handoffs/CURRENT.md)，核对Git与现有实现，不重建应用。
2. Codex负责主开发。按本步技能配方使用Impeccable后台模式、Emil交互与异常检查，保持shadcn/Radix组件合同。
3. 工作台按SBS-0016执行，旧布局缓存原串保全；验证本机任务/事件线/导入闭环、身份隔离及KOL/三方号、搜索与设置回归。MIKO诚实占位，VPC父子导航/旧链/回跳均须验证。
4. 实现者自测后，由未参与实现的审查者核查当前源码、浏览器和截图；通过后才ACCEPTED。规范不能替代实际证据，也不代表用户已主观认可样张。
