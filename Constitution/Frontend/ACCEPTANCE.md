# 前端实际施工验收标准

版本：0.1｜2026-10-18。配套 [规范正文](DESIGN_STANDARD.md) 与 [技能手册](SKILL_PLAYBOOK.md)。

这是页面实现的验收方法；实际UI场景未因写入本文而获得PASS。当前SBS-0010暂停工作台展示/编辑，第3节仅在后续重新开放时适用，本步改验空白页面与既有布局原串保全。适用范围及测试退役映射记录在当前SBS证据中。

## 1. 准入、证据与结论

**FA-01 执行包齐备。** 在动代码前写明当前SBS、规范/视觉token版本、目标仓与HEAD、当前改动、页面范围、数据对象/状态/权限、技能配方、浏览器/设备、性能目标和适用AC。可参考 [模板](../../Product/templates/FRONTEND_EXECUTION_TEMPLATE.md)。未知业务规则不能用样例值补成正式规则。

**FA-02 证据分级。** 静态/类型/构建、mock交互、真实服务、真实用户流程、视觉人工确认分别标注。每条AC使用PASS/FAIL/NOT_RUN/NOT_APPLICABLE；N/A在实施前有范围依据，不能用来抹掉失败。截图至少标注版本/页面/状态/视口/主题/数据性质；浏览器操作证据含输入和预期/实际结果。

**FA-03 完成门禁。** 必需AC全部PASS、无未解决的越权/数据丢失/状态造假/键盘阻断，才进入ACCEPTED。Claude自检后是VERIFYING，独立审查者复查并关闭问题。用户尚未选定的主观视觉方向单独记录，不把技术通过写成“用户非常满意”。

## 2. 每个页面必查

| AC | 关联规则 | 操作与可观察预期 |
|---|---|---|
| UI-01 | FE-06至10 | 从首页/业务入口打开页面，能说明位置、主动作、返回方法；返回保留适用筛选/位置；深链接授权正确 |
| UI-02 | FE-11至17 | 浅/深色、正常/选中/hover/focus状态采用同一token体系，中文标题/数值对齐；所有实际文本搭配测对比度 |
| UI-03 | FE-18至20 | 遍历加载、空、筛选空、错、过期、无权、冲突、未知等适用状态；缺数不变零，保存失败保留输入 |
| UI-04 | FE-30至34 | 两个不同权限身份验证读/写/搜索/导出/订阅；换账号或撤权后敏感缓存不继续显示；后端拒绝不可绕过 |
| UI-05 | FE-31/32 | 两人编辑同一版本触发冲突，不静默覆盖；连续双击/超时恢复不重复造成业务副作用 |
| UI-06 | FE-44至46 | 仅键盘完成主要流程，焦点可见不被遮挡，模态进入/退出正确；辅助技术可读名称/错误/状态；自动扫描不能替代此操作 |
| UI-07 | FE-47/48 | 200%文本缩放、320 CSS px重排和适用文字间距覆盖、长中文/URL/极值/缺失值可用；二维表格局部滚动，外层控件可操作 |
| UI-08 | FE-39至43 | 正常、快速反复开关、拖拽取消、reduced motion下结果正确；无残留遮罩/焦点丢失/等待动画才可操作 |
| UI-09 | FE-33/38 | 示例/模拟/AI推断标记持续存在；模型输出与文件内容不能注入脚本；来源链接权限和安全渲染正确 |
| UI-10 | FE-49至52 | 构建/类型/适用行为测试通过；新增依赖/组件可追溯；无参考仓运行时路径依赖；未测能力如实记录 |
| UI-11 | FE-20/30/34 | 登录允许密码管理器/粘贴等辅助；会话失效后安全恢复上下文；自动更新能按合同暂停/控制频率，旧搜索响应不覆盖新结果 |

纯静态原型可将真实后端相关项按任务范围标为N/A，但交付名称只能是原型，不能称为可生产使用页面。实际写入页面必须覆盖UI-04/05；不能长期以“后端以后补”为N/A理由。

## 6. 性能与动效证据

**PERF-01 测量条件先写。** 执行包注明实际测试设备/浏览器版本、视口、网络、数据规模、冷/热加载、是否mock、并行活动和动作脚本。约40人是产品规模，不能从一台浏览器流畅推导服务端并发达标。

**PERF-02 建议起始目标，需随任务采用。** 本项目默认候选：用户输入/点击获得本地反馈约100ms内；交互trace中不因装饰动效造成连续长任务/明显丢帧；服务器操作的完成时间独立测量，不拿按压动效代替API时延。任务可以采用Web体验指标（如INP/LCP/CLS），但必须在执行包给出指标定义、采样方式和实际阈值，不能把开发机一次测量当真实用户p75结论。

**PERF-03 代表数据。** 默认校验至少包含空、少量、典型与峰值数据；峰值按业务预计数量选择。分页/虚拟化存在时测试焦点、选择、滚动与辅助技术，不能只测FPS。性能不够时先减少不必要工作和动效；不引入大量虚拟化或动画库只为满足纸面架构。

**PERF-04 留存。** 对关键慢动作保留trace/录屏与前后数据，修复后复测同场景；无问题不反复跑无关全量测试。动效正常速度优先，慢速回放辅助；真实触控/低性能浏览器未测时明确NOT_RUN，不假装已覆盖。

## 7. 回执格式

每项写：AC ID → 规范ID → 代码/组件 → 版本与环境 → 操作和输入 → 预期/实际 → 证据 → 结论。缺陷写严重性、复现、影响、修复版本与复验；接受的例外另附原因/责任人/退出条件。审查者复查后按SBS统一结论；不能删除失败截图或用新样例替换不利结果。
