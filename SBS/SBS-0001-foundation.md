本步为文档和 Git 基建。使用文件读取、只读 Git 核查、Markdown 链接及状态检查、独立文本审查。没有业务代码变更，不安装依赖、不运行各组件的产品测试、不启动服务、不调用付费模型。Git 网络请求仅用于既有目标仓库的状态核对和本次授权的基建同步。

## 风险与恢复

- 并发写入：每次 Git 写操作前重查状态；发现陌生变更时先识别归属，不覆盖、不清理。
- 嵌套仓库：命令必须显式指定仓库路径；根仓继续忽略六个组件工作目录。
- 历史清理：VCPAI 的备份先查证，不能因为缺少 remote 就覆盖一个已存在的远端分支。
- 文档误执行：Claude 当前交接入口明确为只读熟悉与等待产品研究，不下发业务代码任务。
- 回退：本次文档独立提交；需要撤销时反向提交本步变更，保留子项目和备份。Git 配置调整记录原值后可恢复。
